# Эксплуатация кандидата «Сейчас» 1.0.0

## Локальный запуск на Windows

Запустите Docker Desktop в режиме Linux containers. Из PowerShell в каталоге
репозитория запустите `./scripts/start-windows.ps1`. Скрипт создаст локальные
ключи при первом запуске, откроет PWA и проверит `/health`. Порт доступен по
`127.0.0.1:8080`. Перед обновлением скрипт проверяет снимок SQLite и сохраняет
его, исходный `.env` и тег прежнего образа в `local-backups`. Храните каталог
как резервную копию персональных данных и ключей. `-Rollback` возвращает данные
и контейнер последнего полного снимка с потерей изменений после его создания.

`./scripts/start-windows.ps1 -Demo` запускает отдельный проект `sichas-demo` на
`127.0.0.1:8081/demo`. Переключайте роли в меню демо. После включения согласия
на уведомления их можно просмотреть на странице демо. Сдвиг времени влияет
только на демо. Остановка демо выполняется через
`docker compose -f compose.demo.yaml down`.

## Linux и PostgreSQL

`compose.production.yaml` — конфигурация для сервера с отдельным терминированием
HTTPS. Приложение привязано к loopback, PostgreSQL доступен внутри сети Compose.
Настройте TLS-прокси, доверенный серверный адрес и политику firewall у себя до
разрешённого запуска. Повторное перенаправление вебхука Telegram требует согласия
владельца. Для приёмки нужен отдельный бот.

В `.env.production` укажите `PUBLIC_URL` (HTTPS), `SECRET_KEY`,
`SELFIE_ENCRYPTION_KEY`, `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_IDS`,
`POSTGRES_PASSWORD` и `DATABASE_URL` в формате
`postgresql://sichas:<urlencoded-password>@postgres:5432/sichas`.
Сам файл и образ без секретов храните раздельно. При переносе старой базы
сохраните исходные ключи шифрования. Для администраторов используйте отдельные
аккаунты. `TASK_MODERATOR_TELEGRAM_IDS` определяет модераторов поручений,
`PRIVATE_TASK_TELEGRAM_IDS` определяет замкнутую группу участников.

Команда ниже создаёт схему **в пустой БД**. Для переноса существующей базы
выполните миграцию по [инструкции](MIGRATIONS.md).

```sh
docker compose --env-file .env.production -f compose.production.yaml up -d --wait postgres
docker compose --env-file .env.production -f compose.production.yaml run --build --rm app python bootstrap_db.py
docker compose --env-file .env.production -f compose.production.yaml up -d --wait app
```

Один процесс Gunicorn запускает фоновые задачи. Для горизонтального
масштабирования отделите фоновые задачи от HTTP-процессов и подтвердите
работу очереди под нагрузкой. Настройте оповещение о недоступности `/health`,
ошибках HTTP 5xx, состоянии очередей, диске и резервных копиях на целевом хосте.
Приложение пишет структурированные журналы HTTP-запросов с идентификаторами.

## Backup и восстановление

Для PostgreSQL создайте архив `pg_dump --format=custom`. Запланируйте частоту
по допустимой потере данных, храните копии зашифрованными отдельно от сервера,
а секреты шифрования отдельно от архива. Разворачивайте архив через
`pg_restore --exit-on-error` в новую изолированную БД и проверяйте `alembic current`,
количество записей и чтение контрольных зашифрованных данных. Возвращайте трафик
после проверки восстановления и миграции.

Для SQLite остановите приложение и сохраните том вместе с ключами `.env`.
Проверьте восстановление на новом томе. Подробности миграции и отката описаны в
[документе миграций](MIGRATIONS.md).

## Перед публичным запуском

На отдельном HTTPS-домене проверьте вход, сохранение сессии, реальную доставку
Telegram с двух тестовых аккаунтов, установку PWA на iPhone и Android, Windows
Docker Desktop, нагрузку и восстановление на целевой инфраструктуре.

С юристом определите оператора и применимые страны, проверьте требования к возрасту
и согласию, защиту и трансграничную передачу данных, сроки хранения и процедуру
удаления, права на съёмку и материалы, правила волонтёрства и работы с уязвимыми
людьми, модель расчётов, налоги, права потребителей и порядок споров.
Публичная версия документов, платежи и выплаты требуют отдельного решения.

## Управление запуском

Администратор открывает /admin и указывает, какие направления принимают новые
действия. Пауза встреч сохраняет выключение статуса. Пауза поручений позволяет
сдать, принять или оспорить назначенное поручение. Пауза «Добрых дел» сохраняет
результаты и отмену записи. Пауза пользовательских Telegram-уведомлений не
отключает служебную доставку жалоб.

В реестре сначала подтвердите организатора на основании согласованных
документов. Затем добавьте координатора с его согласием и публичным именем.
Модератор проверяет общедоступность места и условия каждой акции до публикации.
Отзыв допуска закрывает запись и убирает будущие акции из публичной ленты.
Уже опубликованные акции из старой схемы требуют привязки координатора и
повторной модерации. Подтверждённая ранее история остаётся доступной.

Исполнители указывают город добровольно. Поиск показывает заказчику только
количество подходящих аккаунтов. Для поручения с указанным городом исполнитель
должен выбрать тот же город до отклика. Платёжная интеграция отсутствует.

[Образец TLS-прокси](../deploy/nginx.conf.example) предназначен для хоста
владельца. Прокси перезаписывает клиентские X-Forwarded-* заголовки. Порт приложения
оставьте на loopback. Мониторинг проверяет /ready, где контролируются БД и
активность фоновых циклов, и /health для базовой доступности. Счётчики очереди
находятся в панели управления. Telegram настраивается фоновым циклом.
Прерванная попытка доставки помечается как недоставленная после пяти минут.
При неоднозначном результате повтор исключён, чтобы избежать дублирования.

### Проверяемый архив

```sh
scripts/db-maintenance.sh backup /protected/sichas.dump
scripts/db-maintenance.sh restore-test /protected/sichas.dump sichas_restore_check
```

Команда восстановления создаёт отдельную базу и отказывается перезаписывать
занятое имя. Сохраните копию и ключи в раздельных защищённых хранилищах.
Синтетическая проверка подтверждает чтение схемы и записей после восстановления.
Политику периодичности, внешнее хранилище и оповещения настройте на хосте владельца.

## Telegram с Windows-ПК через HTTPS

Для проверки с действующим ботом запустите Docker Desktop в режиме Linux containers.
Этот сценарий использует отдельный проект Compose `sichas-telegram` с постоянным
PostgreSQL и адресом `127.0.0.1:8082`. Локальная SQLite-сборка на порту 8080 остаётся
доступна со своими данными. Контур Telegram начинает с пустой базы.

Для разовой проверки откройте PowerShell с установленным `cloudflared` и оставьте
туннель запущенным:

```powershell
cloudflared tunnel --url http://127.0.0.1:8082
```

В другом окне PowerShell из корня репозитория передайте выданный HTTPS-адрес
и свой числовой Telegram ID:

```powershell
.\scripts\start-telegram-windows.ps1 -PublicUrl https://example.trycloudflare.com -AdminTelegramId 123456789
```

Скрипт запросит токен `@vmeste_rjadom_bot` при первом запуске и сохранит его
в локальном файле `.env.pc-telegram`, исключённом из Git. Файл содержит также
ключи шифрования и пароль БД. Храните этот файл в защищённом месте вместе с
копией базы. Скрипт сверяет владельца токена и адрес текущего вебхука через
Telegram. Если у бота указан другой вебхук, запуск остановится до его
переключения. Скрипт проверяет доступность приложения и настройку бота через HTTPS.

Quick Tunnel выдаёт временный адрес. Для повторных запусков с тем же ботом
используйте стабильное имя через именованный туннель и собственный домен.
При смене URL отдельно проверьте и согласуйте переключение вебхука. Пока ПК
выключен, спит или туннель остановлен, бот и приложение недоступны.

[Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
