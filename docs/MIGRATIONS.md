# Миграции и rollback

Production-миграции в рамках стабилизации не запускались.

## Перед staging

1. Остановить запись в staging.
2. Сделать проверяемый PostgreSQL backup (`pg_dump --format=custom`).
3. Проверить восстановление backup в отдельную БД.
4. Для существующей схемы 0.17.8 без Alembic выполнить `alembic stamp 0001_baseline`. Для базы на ревизии стабилизации оставить её текущую ревизию.
5. Сверить исходную схему на восстановленной копии.
6. Выполнить `alembic upgrade head` на изолированной копии. Онлайн-режим нужен для перешифрования селфи и очистки старых снимков комнат.
7. Проверить `alembic current`: ожидается `0010_release_controls (head)`.
8. Запустить smoke и concurrency tests.

Миграция сохраняет пользователей и анкеты, переводит старые селфи в закрытый режим,
очищает старые согласия на обмен и убирает снимки комнат из записей повторных
запросов. Для селфи из 0.17.8 нужен прежний эффективный секрет сессии
(`SECRET_KEY` либо использовавшийся вместо него секрет Telegram). Миграция
зашифрует селфи текущим `SELFIE_ENCRYPTION_KEY`. Если расшифровка невозможна,
миграция завершится ошибкой. Для SQLite используйте копию файла без активных
писателей и запускайте ту же последовательность со строкой `sqlite:///...`.

Все команды требуют `DATABASE_URL`. Значения секретов нельзя помещать в
командную строку, логи или отчёты.

Production-приложение не выполняет `create_all()` и отказывается стартовать,
если `alembic_version` отсутствует или отличается от `0010_release_controls`.
Миграции запускаются отдельной командой с `ALEMBIC_RUNNING=1`.

## Rollback

1. Остановить приложение staging.
2. Сохранить новый forensic backup.
3. `alembic downgrade 0007_runtime_guards` удалит таблицы 0.18. Старые согласия, режимы выдачи селфи и снимки комнат не восстанавливаются. Для полного возврата к 0.17.8 используйте исходный backup и прежние ключи.
4. При повреждении данных восстановить исходный backup вместо попытки ручного удаления колонок.
5. Вернуть предыдущий образ приложения и проверить health/read-only smoke.

Baseline — marker-ревизия для уже существующей схемы 0.17.8. Его нельзя ставить
на неизвестную или пустую production-БД без предварительной сверки схемы.


## Переход с 0.18.0 на 0.18.1

После резервного копирования и остановки записи выполните `alembic upgrade head`
с существующей ревизии `0008_safety_good_deeds`. Ревизия `0009_private_features`
добавляет таблицы настроек Telegram, подписок, атрибуции, поручений и откликов.
У существующих пользователей уведомления по умолчанию отключены. Для базы SQLite
в Docker выполните миграцию с той же строкой подключения и с подключённым томом
до запуска новой версии. Для базы, созданной через Compose 0.18.0 без Alembic,
сначала сверьте её схему с 0.18.0 и выполните `alembic stamp 0008_safety_good_deeds`.

Откат на `0008_safety_good_deeds` удаляет новые таблицы и задания очереди
пользовательских Telegram-уведомлений. Аккаунты, встречи, жалобы и профильные фото
сохраняются. Если нужны данные новых модулей, перед откатом сохраните backup.

## Переход с 0.18.1 на кандидат 1.0.0

Сделайте backup и остановите запись. С ревизии `0009_private_features`
выполните `alembic upgrade head`. Ожидаемая ревизия — `0010_release_controls`.
Добавляются условия поручений, защищённые материалы, история и настройки.
Ранее созданные поручения сохраняют сумму и валюту BYN. Новые поля старых
поручений остаются пустыми.

`alembic downgrade 0009_private_features` удаляет таблицы этого дополнения.
Перед откатом сохраните резервную копию, если нужно восстановить материалы
и историю. Базовые поручения и аккаунты сохраняются. Для пустой PostgreSQL
используйте инициализатор из [инструкции эксплуатации](OPERATIONS.md).
